## 접근 방법

핵심 아이디어는 괄호 짝을 스택처럼 처리해서 여는 괄호 '('를 만나면 저장하고, 닫는 괄호 ')'를 만나면 스택에서 하나를 꺼내는 방식으로 문자열을 검사하는 것이다. 구현상에는 collections.deque를 사용해 append/pop 연산으로 스택 동작을 흉내 내고 있다.

코드의 흐름은 다음과 같다.
- answer, cur_s, cur_b 등을 초기화(단 cur_b는 실제로 사용되지 않음).
- 문자열 s를 순회하면서 각 문자와 인덱스를 확인:
  - 만약 첫 문자(idx == 0)가 ')'이면 즉시 False 반환.
  - 문자가 '('이면 deque에 append하고 cur_s를 '('로 설정.
  - 문자가 ')'이면 (len(queue) > 0) & (cur_s == "(")가 참일 때만 queue.pop()로 하나 제거한다.
    - 여기서 논리 연산에 비트 연산자 &를 사용하고 있음.
- 순회가 끝난 뒤 queue가 비어 있으면 True, 아니면 False 반환.

따라서 구현은 기본적으로 스택(여기서는 deque)을 이용해 열린 괄호의 개수를 관리하고, 닫는 괄호를 만났을 때 조건을 만족하면 pop하는 방식으로 동작한다.

## 시간복잡도

- 시간복잡도: O(n)
  - 문자열을 한 번만 순회하므로 n은 s의 길이. 반복문 내에서 append/pop/len 등은 O(1) 연산이므로 전체는 O(n).
- 공간복잡도: O(n)
  - 최악의 경우 모든 문자가 '('이면 deque에 모두 쌓이므로 추가 공간은 입력 길이 비례.

이 판단은 코드가 입력을 한 번 순회하고(deque에 최대 n개 저장 가능) 각 문자에 대해 상수시간 연산만 수행하는 점에 근거한다.

## 회고

배울 점
- 괄호 짝 검사 문제에서 스택(deque)을 사용하는 접근 자체는 적절하다. append/pop으로 열린 괄호의 수를 관리하는 방식은 직관적이고 효율적이다.

불필요하거나 복잡한 부분
- from collections import *: 필요한 이름만 import하는 것이 더 명확하다.
- cur_b 변수는 선언만 되어 있고 코드 어디에도 사용되지 않으므로 제거해야 한다.
- list(s)로 다시 리스트화하는 것은 불필요하다. 문자열 자체로 순회 가능하다.
- cur_s 변수는 '('를 만났을 때만 설정되고, pop 이후에는 갱신되지도 않으므로 사실상 불필요하다. 닫는 괄호 처리에서 cur_s=='(' 검사 대신 단순히 queue의 비어있음 여부만으로 판단해도 된다.
- 논리 연산에 and 대신 비트 연산자 &를 사용하고 있다. bool에 대해서는 동작하지만 가독성과 관례 면에서 좋지 않다.

놓친 예외 케이스 / 논리 오류 가능성
- 코드가 첫 문자에 대한 닫는 괄호는 즉시 False로 처리하지만, 이후 위치에 나오는 불일치 닫는 괄호는 처리하지 않고 무시한다. 예를 들어 s = "())"의 경우:
  - idx0 '(' → push
  - idx1 ')' → pop (스택 비어 있음)
  - idx2 ')' → 스택이 비어있으므로 아무 동작 하지 않음
  - 최종적으로 스택이 비어있어 True 반환
  실제로는 여분의 닫는 괄호가 있으므로 정답은 False다. 따라서 현재 구현은 중간에 스택이 비어 있는 상태에서 닫는 괄호를 만났을 때 바로 False를 반환해야 하는 요구를 만족시키지 못한다.
- cur_s를 이용해 '('가 있었는지를 체크하려는 의도처럼 보이나, cur_s는 한 번 '('을 만나면 계속 '('로 남기 때문에 닫는 괄호 처리 로직에 실질적인 의미를 주지 못한다. 이로 인해 닫는 괄호가 매칭되지 않을 때 즉시 에러로 처리하지 않는 원인이 되지는 않지만, 불필요한 상태 변수가 되어 코드 이해를 방해한다.

더 단순하고 안전한 방법(설명만)
- 닫는 괄호를 만났을 때는 단순히 스택이 비어 있으면 False를 반환하고, 그렇지 않으면 pop하는 식으로 처리하면 예외 케이스를 놓치지 않는다.
- cur_s와 같은 보조 변수를 제거하고, 비트 연산자(&) 대신 and를 사용하면 가독성과 안정성이 올라간다.
- 스택 대신 정수 카운터를 사용해 열린 괄호의 수만 관리해도 동작을 만족시킬 수 있다.

요약하면, 현재 구현은 기본 아이디어는 맞지만 닫는 괄호가 스택이 비어 있는 경우를 즉시 처리하지 않아 일부 입력에서 잘못된 True를 반환한다. 또한 불필요한 변수와 비표준 연산자 사용으로 코드가 다소 복잡해 보인다.

## 코드

```python
# https://school.programmers.co.kr/learn/courses/30/lessons/12909

from collections import *


def solution(s):
    answer = True

    queue = deque()
    cur_s = ""
    cur_b = "d"

    for idx, i in enumerate(list(s)):
        if (i == ")") & (idx == 0):
            return False
        elif i == "(":
            queue.append(i)
            cur_s = i
        else:
            if (len(queue) > 0) & (cur_s == "("):
                queue.pop()

    if len(queue) == 0:
        return True
    else:
        return False
```
